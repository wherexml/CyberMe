# 本机技能：目录、自动采用、明确调用与跨轮续办

状态（2026-11-13）：源码实现完成，**已完成签名安装、目录路由、原生技能列表/详情及数据保留验收**；具体分层结果与未覆盖范围见文末。实现前失败面见本机私有验收记录（18 项，三批共用），本文只列公开边界。本文补充 [明确交办的通用执行](agent-execution.md)、[持续单一 Agent 会话](agent-session.md) 与 [持续 Agent 消息追加](chat-input-append.md)，不改变其中原有契约，除非下文明确写“取代”。

## 实现前失败面（摘要）

1. 正则解析丢失多行 YAML 描述；缺省名称、根 Markdown、嵌套目录、符号链接、同名冲突、`.system` 发现回归。
2. `~/.agents/skills` 不默认可见；SDK 根目录继承其他 CLI 设置或启用扩展。
3. 超过 300 项时目录被截断；manualOnly 进入自动候选，用户直接要求查看手动技能反被拒绝。
4. 自然语言交办只得到技能介绍而没有实际工具动作和回读；非零退出、假成功或仅模型回复被当成目标完成。
5. 斜杠在 prompt 包装后失效；正常/追加路径不一致；引用、代码块或外部消息触发技能或授权。
6. 技能正文被当作用户授权；技能内额外的发送/删除扩大目标；已有目标却要求用户重复选择和授权。
7. 普通消息获得无限制命令；只读、自主权限、外发批准与暂停被绕过。
8. “继续”不能承接原工作，或在多个可能目标时默认最新；换题/停止后继承旧权限。
9. 源消息删除/遗忘/取消后恢复授权；跨会话泄漏；追加输入绑定到其他 run；迟到工具继续写入。
10. 新 runId 绕开未知操作账本；同一步重跑产生重复效果；凭证引用指纹误判。
11. 固定期限/续办次数导致正确工作丢失；成功、失败、partial、unknown 与单纯读取混淆。
12. 技能修改后缓存不刷新；目录 mtime 未变时漏掉嵌套文件变化。
13. 压缩/恢复重复堆目录；技能正文占满上下文；恢复已遗忘的交办。
14. 路径逃逸、二进制、超大文件、错误 offset；正文、凭证或业务数据进入审计。
15. 设置页仍是能力登记或保留无实现的开关；加载失败仍显示旧详情。
16. 关闭/回滚后旧目录与授权继续生效；旧 operation 键不兼容。

## A. 目录、自动采用与明确调用

**目录来源**（`server/src/skill-catalog.ts`，聊天工具、模型目录、明确调用与 HTTP 共用一份）：有界发现适配器按 SDK 发现规则遍历固定根目录（含 SKILL.md 的目录即一个技能且不再深入；跳过点目录与 node_modules；根目录直接的 `.md` 为单文件技能），记录已访问真实路径以跳过符号链接循环，限制深度 8、单目录 2000 项、技能总数 3000，并在读取任何清单前检查普通文件与 256 KiB 上限；每个触及的上限都写入诊断（`skill_symlink_cycle_skipped`、`skill_depth_limit`、`skill_dir_entry_limit`、`skill_count_limit`、`skill_file_too_large` 等），诊断超过 200 条时以 `diagnostics_truncated:N` 计数。清单解析仍用已安装 Pi 1.3 SDK：技能目录用 `loadSkillsFromDir`（遇到 SKILL.md 即返回，不递归），根目录 Markdown 用 `parseFrontmatter` 并沿用 SDK 规则；不恢复正则 YAML。忽略文件仅在技能目录内由 SDK 处理，根目录与中间目录的 `.gitignore/.ignore/.fdignore` 不再参与发现（已知差异）。`DefaultResourceLoader` 仍为 `noSkills/noExtensions/noContextFiles`，不升级 SDK、不启用扩展、不解析包。默认顺序：

1. `ROOT/skills`（应用数据）
2. `~/.agents/skills`
3. `~/.pi/agent/skills`
4. `~/.codex/skills`，以及显式的 `~/.codex/skills/.system`（SDK 跳过点目录）
5. `~/Projects/skills`（兼容）
6. `CODE_ROOT/server/agent/skills`（内置回退）

`CYBERME_SKILL_ROOTS`（绝对路径 JSON 数组）整体替换上述列表；HTTP 与模型参数不能增加根目录。同名技能先出现者生效，后者记为 shadowed 可查；同一真实文件只计一次（别名保留）。YAML 多行描述、缺省名称（父目录名）、嵌套目录、根目录 `.md`（需有 description）、`disable-model-invocation`（manualOnly）、忽略文件均按 SDK 规则。超过 256 KiB 的清单与无法读取的文件进入诊断而非目录。根目录 Markdown 技能只拥有该文件本身，不能读取其所在根目录的其他文件。

**缓存与刷新**：缓存只是优化。每次访问都核对已知清单文件的 mtime/大小和根目录 mtime，编辑立即生效；新增或删除嵌套技能最迟在 `CYBERME_SKILL_CATALOG_TTL_MS`（默认 10 秒）后发现。`read_local_skill` 每次读取真实文件并返回当前 sha256。

**模型目录**：持续会话中注入一条可替换的 `cyberme_skill_catalog` 服务端资料：所有可自动选用技能的名称索引，在 9000 字符预算内附短描述，超出部分只列名称并提示用 `list_local_skills(query)`；manualOnly 只计数不列出。另有每轮替换的 `cyberme_skill_hints`（≤3000 字符）：按当前请求的名称/描述词项匹配给出最多 8 项完整一些的描述。两者合计约 12k 字符上限，不调用额外模型或路由器。名称索引本身超出预算时，不截断名称：已列名称完整，其余以“另有 N 个名称未列出”如实说明并给出 `list_local_skills(query)` 回退（审计 `namesOmitted`）；明确点名、斜杠调用与每轮相关提示始终检索完整目录，因此靠后的技能仍可到达。目录 hash 变化、压缩或遗忘清理后重发，旧副本以 context edit 移除；不改变会话指纹，下一轮即生效而不重建逻辑会话。一次性直接聊天（无持续会话）以同样内容作为提示资料；内部任务、来源受限任务、草稿和后台分析不注入。

**manualOnly**：不进入目录，`read_local_skill` 对自动读取返回 `skill_manual_only`。区分两种明确用法：用户原话只点名该技能（如“看看 demo-manual 写了什么”）时可读取，属于查看；用户原话直接要求使用它（“使用/用/按/调用/运行/执行/采用 demo-manual …”、“use/run/apply demo-manual …”）或以斜杠调用时，视同明确选用，可作为本目标的方法（`skillRef` 被接受），无需用户改用斜杠。判断基于去除引用、代码块、`<quoted_context>` 与否定分句（“不要/不用/别 使用 X”）后的用户原话；来源资料与技能正文从不构成选用。命名选用记录 `skill_named_use`（含 `bare`），并以服务端提示告知模型。去除“使用 X”短语与客套词后仍有具体任务时（如“请使用 demo-manual 保存公开验收标记”），与 `/技能 参数` 一样按该技能工作流授权，evidence 仍须引用用户原话；只有选择而无任务时（如“使用 demo-manual”）与无参数的 `/技能` 规则相同：恰好一个有效工作目标时以该技能继续它，否则只询问缺少的目标或参数，不构成执行授权。

**明确调用**：在任何包装之前解析原始用户输入（普通轮次与安全消费点的追加输入一致）。只认开头的 `/skill:名称` 或 `/名称`（其后为空白或结束）；路径如 `/Users/x`、引用、代码块和来源资料不解析。`/skill:未知` 及形如命令名的未知 `/名称` 得到“未找到”的事实说明，文本照常交给模型；其他斜杠文字按普通文本处理。命中时注入 `cyberme_skill_invocation`：技能正文（≤24000 字符，其余分页读取）、路径、来源与 sha256，明确标注为受信任的本机方法资料、无用户授权效力；当前用户原话仍是唯一证据来源。参数原样保留。审计 `skill_invoked` 只记录 id/hash/路径/来源与参数摘要。

**自动采用**：模型按目录选择相关技能，`read_local_skill` 读取后用现有业务工具或 `run_command` 推进用户已交办的目标并回读。`run_command` 可带 `skillRef {id,hash}`，必须匹配本轮（或当前工作范围）实际读取/调用的当前清单 hash，否则 `skill_ref_invalid`；它只记录方法来源，从不授权。读取、动作成功（退出码/回执）和目标达成（回读）分别报告；轮次 `taskOutcome` 仍只依据实际回执。

**上下文回收**：轮次结束后，`read_local_skill` 结果与调用正文在上下文中替换为 id/hash 存根（需要时重新读取），遗忘/删除与压缩清理沿用现有会话卫生规则。

## B. 跨轮工作范围与续办

内部记录 `agent_work_scopes`（通用实体存储，无新 SQL 表、无界面、无调度）。只保存 id 与 hash：会话、原始 run/request/用户消息 id、原交办 hash、选定对象 id、技能引用（id/name/hash/是否明确调用）、绑定的 run、状态。原交办正文每次从原消息读取。

- **建立**：直接聊天的非只读输入，若当前原话构成执行交办（既有执行判定）或是带参数的 `/技能 参数`，建立范围。新的非续办直接输入关闭本会话其他未完成范围（`topic_changed`）；追加输入是补充，不关闭正在进行的工作。
- **续办**：整条消息仅为“继续/接着/按这个做/continue/go on”等，或只点名一个技能（无参数）时，若本会话**恰好一个**有效未完成范围（或用户本轮选定的对象恰好与一个范围的对象完全一致），则本轮以原交办原文作为工具授权依据（evidence 须逐字引用原交办），服务端以 `cyberme_work_scope` 说明来源与未确认步骤；外层 prompt 仍是用户本轮原话，不以旧文本替换。没有或多个候选时不绑定，只确认目标，从不默认最新。唯一候选而用户选定了不同对象，即确认换了目标：该范围关闭为 `target_changed`（已记录操作保留可回读），之后不带对象的“继续”也不会恢复它。不设固定期限或续办次数。
- **失效**：原消息删除、被遗忘/撤销（`excludedRunIds`）、原文变化、所属轮次被停止或被新消息打断、选定对象删除、范围已完成，以及换题，均使范围关闭。只读输入、来源受限与内部任务从不绑定或建立范围；只读、自主权限、发送批准与来源限制在每次调用时照常检查。
- **完成**：轮次成功且回执结果为 `succeeded`、无未知步骤时范围完成；`partial/failed/pending/not_executed` 或超时保持打开以便续办，停止则关闭。
- **操作身份**：范围内 `run_command` 键为 `scopeId + operationId`，`app_action` 等业务写入键为 `scopeId + 动作/对象/输入`（去掉 run 本地字段），跨轮与重启遇到同一回执：已成功回放原结果，运行中/未知要求先回读（`execution_requires_readback`/`operation_requires_review`）；同一范围内相同参数的未知步骤换 operationId 也被拒绝。范围内凭证按密钥指纹（非值、非运行内引用）参与参数指纹；指纹变化即 `execution_conflict`，新步骤须用新 operationId。无范围的旧记录与键保持不变。
- **重试**：同一 requestId 的重试（`run.retryOf`）与新请求显式 `retryOfRunId` 都关联被重试运行所属的原范围（原运行或其任一续办运行），沿用原范围键与回执，未知步骤先回读。以下情况拒绝关联：被重试运行不存在或属于其他会话、范围已完成、已因遗忘/删除/原文变化/停止/对象删除/换目标关闭、重试消息与原交办原文不同（`retry_payload_changed`）、选定对象不同（`retry_target_changed`）；被重试运行无范围但有未确认的旧键操作时也拒绝（`retry_requires_readback`）。拒绝时本轮所有会改变状态的工具调用都在统一分发层被拒绝（`execution_retry_blocked`）：`run_command`、业务写入、偏好保存、来源规则、持续跟进创建/操作，以及非预览的批量 Inbox 变更；读取、回读、批量预览、技能读取与 GitHub 只读工具仍可用。本轮消息不替代原授权，只能回读并告知。追加输入以同一方式传递该阻断。仅因后续换题而关闭的范围可被精确重试重新打开。被重试运行既无范围也无未确认操作时按普通新请求处理。只读输入不参与重试关联。
- **追加输入**：每个追加输入在消费点独立绑定；只读追加不继承写权限；续办只能绑定本会话的范围。
