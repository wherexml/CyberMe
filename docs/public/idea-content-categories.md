# 灵感内容分类

## 实现前失败面

- 将内部 insight/automation 类型显示为「规律/例行」，掩盖内容主题。
- 只改新建议，旧卡片仍显示旧标签；每次打开重新分类，标签漂移。
- 模型返回空泛、过长、命令、未知 ID、重复或缺失结果；失败时清空旧分类。
- 分类期间原文编辑、删除、忽略；迟到结果覆盖新内容或恢复旧卡片。
- 只补分类却改动原消息、正文、状态、来源时间、更新时间或触发新推送。
- 同义分类越分越多，筛选按钮与卡片不同步，窄屏溢出。
- 实际模型逐条命名导致 49 条生成 45 类；必须先从整批内容归纳少量主题，再统一归类。
- 全局主题生成失败、空标签、重复标签、超过上限时不得写入分类；旧版本细碎分类需重新归类。
- 实机模型在归类步骤又创建新类，突破全局主题约束：归类只能引用全局主题，新增主题必须经过单独的全局归纳步骤。
- 仅浏览器通过，安装版遗漏模块或代理路由。

## 约定

AI 先从整批有效卡片归纳最多 10 个主题，再逐批归类；归类结果只能引用本轮全局目录，不能逐条新建类别。分类名没有固定预设，不使用内部四类映射。内部 category/action 继续负责原处理语义。新生成建议同时返回分类；已有建议通过独立无工具模型批次补齐，只读取标题和正文。复用语义相同的既有分类，新主题命名由全局归纳步骤负责；没有有效分类显示中性「待分类」。

分类携带版本标识，以标题/正文指纹绑定并持久保存，原文变化后旧分类失效。补分类不改原文、状态、证据、创建/更新/提醒时间；模型输出不是执行授权。并发请求合并，提交前复核记录，失败保留原数据，后台有界重试，中断不自动重放。

早期分类界面的卡片与筛选使用同一个分类字段。当前 [合并洞察流](insight-visuals.md#界面) 隐藏分类名和筛选控件，仍保留分类的生成、存储和 API 投影。下方浏览器与安装版的筛选结果属于旧界面；HTTP 分类验证独立于界面。
