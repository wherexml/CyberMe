# 工作区启动与收件箱跳转性能

## 实现前记录的失败面（2026-11-05）

- 本机 API 已监听但同步工作长时间占用事件循环；健康检查超过 1 秒，被原生启动检查判为失败，完整收件箱显示启动报错。现场一次健康检查耗时 15.56 秒。
- 更新一个来源收件箱时为寻找关联请求轮次，反复读取并解析整个收件箱；后台批量同步会放大数据量与阻塞。
- 性能修复不得漏更新关联轮次，不得改写其他来源、已删除轮次、草稿和发送回执；来源变化仍撤销审批。
- 列表与判断优化不得复用过期证据：任务、记忆、设置、来源、连接权限和时间到期必须立即生效。
- V6 首屏依次等 bootstrap、模型设置、主会话和工作进度；慢辅助接口不应挡住已取得的工作区，重复刷新不得叠加请求或以旧响应覆盖新快照。
- 完整收件箱必须保留精确事项深链，跳转只读取，不能触发外发或重放请求。

验证采用独立五位端口、合成大收件箱数据的 HTTP E2E 与浏览器故障注入，保存 JSON/截图。真实安装版与隔离结果分别记录。

## 修复

- 收件箱关联轮次使用 `sourceParentInboxId` 的部分索引精确读取；不再在每次来源同步写入时解码整个收件箱。
- 同一同步列表投射只读取一份任务、忽略反馈和身份设置；不跨调用缓存。单条证据语义版本继续复用，跳过不会参与该版本的旧传输指纹。每次新读取仍核对当前来源、权限、依赖和时间。
- Inbox 主对话投射以 1 秒计时器合并来源更新，给 HTTP I/O 留出执行机会，不再在每个同步微任务之后立即全量投射。
- V6 从 bootstrap 的 `sources.primaryConversationId` 取主对话，立即显示工作区；模型设置和工作进度独立补充，失败不清空已显示的工作区。同一轮刷新共享 Promise，辅助读取上限 15 秒，旧对话的工作响应不能进入当前对话。
- 完整收件箱入口解析精确事项 ID，读取当前记录、切到“全部”、清除搜索并显示详情。包含待核实/安静项，不触发草稿生成或发送。此前仅解析页面名、忽略事项 ID 的行为已修复。

## 复验与结果

1. `node --import tsx scripts/workspace-startup-http-e2e.mjs`：233 条大正文合成来源；100 次更新、关联轮次/删除记录/其他来源隔离、草稿与回执、审批失效、bootstrap 和精确详情、任务/身份/反馈变化后的判断失效，共 16 项通过。
2. `npx vite build --config web/mygo.vite.config.ts --outDir ../.local/workspace-startup-web`，再运行 `node --import tsx scripts/workspace-startup-fixture.mjs`（46849），使用 `ego-browser nodejs < scripts/workspace-startup-browser-e2e.mjs`：8 项通过。刻意挂起辅助接口，首屏 201ms 可输入；精确收件箱跳转 507ms；无业务写入。浏览器脚本保留 TaskSpace，协调者查看截图后执行 `finish({keep:[]})`。
3. 类型检查、桌面构建、`git diff --check` 通过。

性能对照：同一私有数据库副本的 100 次来源更新从 13,860ms 降至 103ms；属于数据路径测量，不是原生启动耗时。HTTP/浏览器结果与截图位于忽略目录 `output/workspace-startup-20261105/`。

## 本机安装验证

2026-11-05 安装 0.1.3 / build `1793870867735`，保留应用标识与用户数据，Developer ID 同团队签名验证通过。本机更新，有旧包备份；未发布互联网版本、未对此构建做新公证。

实际 App 冷启动进入 V6，点击用户报告的事项详情及“在完整收件箱中打开”，精确事项选中、详情可见，没有启动错误；返回 V6、正常退出重开后界面可用。原生 WebKit AX 首次显示不完整，未取得可靠的原生首屏计时，不将浏览器 201ms 当成安装版耗时。冷启动 API 就绪后的 9 次健康采样为 3–748ms（此前单次 15.56 秒）；现场另一次 bootstrap 为 2.59 秒，不能宣称所有接口瞬时返回。

233 条收件箱的 draft、editedByUser、approved、receipt、receipts 均无变化；前序意图验收的五条负样本仍不进入简报，正样本仍保留。回执、签名/源码一致性、健康采样和脱敏验证在 `output/mygo-startup-20261105/`。未重发模型请求、未外发消息。验证范围是本机本次运行，持续同步峰值与 OS 重启后的全部时序未穷尽。

退出重开后的连续 20 次健康检查全部成功，3–947ms，中位数 347ms。实际数据下仍存在短暂计算负载，未将其描述为零等待。
