# 主对话摘要位置与 PR 查询

## 实现前失败面

1. 三小时摘要到期时，旧来源动态会因投递时间排到刚发的用户消息后面，看起来像本轮回复。发送、轮询和重载不能重复投递；主会话有进行中的请求时，摘要仍在队列中，但已失效的旧行要照常撤回。
2. 每个摘要用有效行中最新的原始时间定位，缺失原始时间时沿用投递时间；不改持久时间、分页游标或摘要与原记录的精确关联。正在回复的对话不显示来自旧来源的新插队卡片。
3. 仅查询 PR 时，通用命令把成功的读取计为可能的写入；管道也可能掩盖 GitHub CLI 错误。PR 读取只用已核实的仓库与编号、固定 GET、不进 shell、限制时间和输出；权限、找不到、超时、分页和缺失 diff 不能伪装成完整结果。
4. 读取完成后的模型超时应为失败且可显式重试；任意命令或已有写入的未知/部分结果仍禁止重放。超时、用户打断和服务重启使用各自的原因；旧结果只读回查，不改原记录。
5. 验收使用独立服务、数据和受控模型，不重跑原 PR、不访问私有仓库、不在验收截图或日志中复制真实业务内容。
