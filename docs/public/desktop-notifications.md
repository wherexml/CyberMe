# 本机主动提醒与 macOS 通知

## 2026-11-10 摘要点击定位：实现前失败面

- 通知 ID 含摘要消息 ID，但当前点击只打开主对话；有更新消息或用户向上滚动时，必须定位到原摘要，不能停在最新普通消息。
- 从侧会话或退出状态点击，导航意图须等待主对话加载；旧请求响应、下一次点击或用户滚动不能把焦点拉回过期目标。
- 目标不在首屏需要按已有分页定位；撤回、缺失或读取失败应明确无法定位，保留用户草稿，不跳到另一份摘要冒充成功。
- 实际自动投递须区分应用回执、macOS 专注模式拦截、横幅和声音播放；不能拿测试按钮或合成通知代替。

## 2026-11-10 洞察摘要的桌面通知：实现前失败面

- 开启 macOS 洞察通知后，摘要档位生成新「最新动态」仍没有横幅；一份摘要只发一次，不按行打断，不改变主对话档位。
- 升级前的摘要、关闭期间已经生成的摘要和积压的旧摘要不能补弹；重复轮询、重启和未知回执不得重复提交。
- 纯请求摘要不属于 macOS 洞察通知；洞察来源变动、撤权、静默、视觉版本更新和摘要撤回后，提交前复核必须阻止失效通知。
- 免打扰或切换投递档位发生在领取之后时，复核不能放行旧通知；通知内容不带原文，点击只回到主对话和洞察。
- 设置读取失败不能让「测试通知」失效，也不能把未知的开关状态显示为关闭；移除未接通的推送方式、阈值、任务审批和任务失败控件。

> 2026-11-10：开启 macOS 洞察通知后，单条模式仍通知新洞察，摘要模式只为新「最新动态」发一次通知。免打扰仍阻止自动提交；紧急请求、发送恢复和不含有效洞察的摘要仍留在应用内。测试和自动通知使用系统默认提示音，遵循 macOS 的展示与声音设置。

## 实现前失败面（2026-11-05）

- 本机安装版已经进入 V6，但 Dock、旧版本号及经典入口容易混淆；须核对实际安装路径、原生资源与后台，不用源码预览代替安装。
- DeepSeek 内部 JSON 输出模式可能跳过调查工具，主动洞察失败为 `idea_research_required`；需要先完成有界只读调查，再返回 JSON。不得绕过逐字证据校验。
- 真实批次返回 13 条建议而契约最多 8 条：只允许在原只读会话和原超时内纠正一次；仍超量或证据错误必须失败，不能截取后伪装全部有效。
- 只有主对话派生消息，没有 macOS 系统投递；设置开关不能伪装成功。
- 首次开启不能补推历史；重启、重复轮询和系统回执丢失不能重复投递。旧消息撤回、断连或来源变化不能继续推送。
- 通知禁止泄露业务正文；点击只打开本机主对话和简报，不执行任务或外发。
- 拒绝权限、系统免打扰、应用退出、后端不可用必须区别于可见弹出。系统接收请求不等于用户实际看见。
- 重复点击测试不能复用同一系统通知 ID，否则 macOS 可能只替换已有项而不重新显示横幅；业务提醒仍必须使用稳定 ID 去重。
- 关闭开关或免打扰期间不能新提交；首次授权失败不启用设置；配置冲突保留当前状态。

## 范围

本次用户选择应用内提醒和 macOS 系统通知。飞书、个人微信是读取来源，不启用飞书私聊通知或微信发送。保持既有自动同步及人工审批边界。

系统通知当前覆盖主对话中经过来源复核的新洞察及含有效洞察的新摘要，使用统一提示，不展示业务正文。任务失败和待审批的独立系统通知未接入，设置页不显示对应控件。

## 行为

- 设置 → 洞察与通知 → macOS 洞察通知，经原生 MyGO `Notification.Show` 请求系统权限，系统接收测试通知后才保存开启。显式测试不依赖后端和自动投递策略，浏览器预览不显示原生控件。
- 原生进程每 10 秒读取 `/api/native/notifications`。逐条模式只选择开启后 24 小时内的有效单条洞察。两种摘要模式仅考虑当前主对话中升级及启用后生成的最新摘要，最长有效期为既有的三小时摘要间隔；至少一条洞察仍通过来源和视觉版本复核才可发出。领取、撤回或失效不会让更旧的摘要补弹。
- 系统通知 ID 绑定消息；先耐久登记 submitted，再复核，最后交给 macOS 并记录 accepted/denied/failed。提交后的未知回执不自动重试，避免进程崩溃或响应丢失造成重复。accepted 仅代表系统接收，专注模式等仍可能不展示横幅。
- 点击通知打开 CyberMe。摘要通知按原消息 ID 回到主对话并定位对应「最新动态」；应用由通知冷启动时，等待工作区加载后再定位。需要时最多读取四页历史，目标已撤回或读不到则提示无法定位。其他洞察通知仍打开主对话和洞察。已存在的草稿不清空，点击不会执行任务或外发。配置有版本冲突保护；关闭或重新开启不会补推期间积压。
- 原生进程运行时才有系统通知；退出应用后的常驻通知服务、登录自启不在本次范围。API 后台分析和原生通知是两个不同的运行状态。
- DeepSeek 的主动调查首轮先要求 `search_idea_sources`，此时不启用 JSON-only 输出；实际工具成功后再生成 JSON。4 次调查上限、整体超时、逐字引用和提交前来源指纹复核保持不变。
- OpenAI 与 Anthropic 兼容协议分别使用各自的指定工具参数。格式、条数或证据不合格只在原只读会话内纠正一次，仍不合格保留失败；没有放宽引用、来源和条数规则。

复验入口：`node --import tsx scripts/desktop-notifications-http-e2e.mjs`、`node --import tsx scripts/chat-insight-quality-e2e.mjs`。真实模型必须使用实际已配置的运行实例；无项目配置的 `--real` 不能替代安装版验收。

## 验收

先以公开来源的 HTTP E2E 覆盖启用、历史隔离、去重、撤回、来源变化、免打扰、关闭及配置冲突，再构建签名安装包。实际 macOS 权限、系统通知、点击返回与真实模型主动分析分别核验，产物保存在忽略的 `output/`，不复制私人正文。
