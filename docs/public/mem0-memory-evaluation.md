# Mem0 与 CyberMe 记忆评估

> 2026-11-11：下方「项目隔离上线」的范围规则已退役，恢复单一全局个人记忆库。Mem0 仅作为召回引擎（单一 `global` 索引、9 秒上限、失败回退关键词召回）保留。现行规则见 [全局个人记忆](global-memory.md)；`mem0-project-*` 脚本断言旧隔离行为，不再用于验收。

## 项目隔离上线（2026-11-09）

### 失败清单

- 在 A 项目问 B 项目，返回 A 的联系人。标题重复、名称有歧义、项目已移除或选定资料矛盾时仍注入项目记忆。
- 同槽位或同一原句在 A、B 互相覆盖、去重或被一起忘记；模型提取拿到其他项目的槽位提示。
- 无范围的旧记录被推断成项目记录，或项目事实经全局提取、人物状态进入全局档案。
- 客户端、模型、标题子串、附件或引用决定范围；切换项目时旧历史被移动；重放或后台任务换了范围。
- 异步召回期间来源修改、忘记或项目移除后，旧结果仍注入；一个范围的批准结果在另一范围生效。
- 模型或 SDK 不可用时阻塞聊天，证据把回退写成 Mem0；密钥被复制或记录。

### 范围规则

范围只来自服务端的 `conversation.memoryProjectId`。无此字段为全局。项目会话只由 `POST /api/chat/memory-scope` 按真实 `projects.id` 创建，每个项目一个专属会话，之后不可修改，也不会成为主会话。切换项目即切换会话，旧历史不动。选择随现有界面状态保存，刷新和重启后保留。

| 记忆类型 | 全局会话 | 项目会话 |
| --- | --- | --- |
| 本项目自动记忆 | 不可见 | 可见 |
| 其他项目自动记忆 | 不可见 | 不可见 |
| 全局自动记忆、手写 MEMORY | 可见 | 不可见 |
| 身份、结构化偏好、全局沟通偏好 | 可见 | 可见，同键项目偏好优先 |
| 人物状态（仅全局写入） | 按原规则 | 按原规则读取，不写入 |

候选排序、关键词回退、槽位去重与替换、提取提示、初始化、忘记、撤销和上下文注入都按同一范围过滤。旧记录没有范围，只属于全局。

项目会话收到点名其他项目、名称重复或已移除、选定资料属于其他项目的消息时，`POST /api/chat` 在写入消息、打断旧回复或读取会话历史之前返回 409 `memory_scope_conflict`。这种请求不会创建运行，只留下 `chat_requests` 失败回执（`scopeConflict.reason`）。`GET /api/chat/requests/:id` 返回 `failureCode=scope_<reason>`，V6 显示具体原因且不提供重试。绑定项目已移除、范围声明不一致同样留下回执。全局会话和旧客户端不受此拦截。检索抑制保留为并发时的第二层保护。只匹配项目标题和去掉「项目/工程/project」后的名称，至少 2 个字符，最长名称优先。提到其他项目的消息不写入当前范围；全局会话里提到项目的消息不写入全局。

模型的普通查询也遵循同一范围。`list_entities`、`runs_list`、`run_get`、`entity_list`、`entity_get` 隐藏其他范围会话的运行和会话记录，并对所有会话隐藏 `memory_extract`、`context_summary` 内部运行。项目会话读不到全局 personal/preference 记忆和 MEMORY 文档，`save_memory` 及记忆写操作返回 403。相同 `requestId` 从另一会话重放时，只要任一方绑定项目就返回 409 `request_conflict`；两个未绑定会话保持原行为。

### 召回引擎

普通桌面聊天使用 `mem0ai/oss@3.3.1`，每个范围一个懒加载内存索引，SDK 遥测和历史库关闭。端点和密钥沿用 `omlxConfig()`：`OPSTWIN_OMLX_BASE_URL`（仅本机五位端口）、`OPSTWIN_OMLX_KEY` 或 `~/.omlx/settings.json`。嵌入模型可用 `OPSTWIN_OMLX_EMBEDDING_MODEL` 覆盖，`OPSTWIN_MEM0_RECALL=off` 关闭。

Mem0 只产出候选键。注入前重新解析范围并读取有效原句。单轮最多等待 9 秒；失败或超时回到同范围关键词召回，模型失败后 60 秒内直接回退。运行证据 `load_user_context.recall` 记录 `method`、`engine`、`fallbackReason`、`scope`、`projectId` 和 `suppressedReason`。

### 复验

依赖安装由本机协调方完成。确定性检查（隔离合成库，不调用真实模型）：

```sh
node --import tsx scripts/mem0-project-scope-e2e.mjs
```

该脚本覆盖同槽位同原句、旧记录、跨项目点名、重名、移除、矛盾资料、替换、忘记、来源变化、跨范围批准、模型停机和重放绑定。以下需在隔离实例手工确认：

1. 输入框上方选择项目后进入专属会话，刷新和重启后范围不变，切回全局时旧历史仍在原会话。
2. `PATCH /api/conversations/:id` 修改 `memoryProjectId` 返回 409 `memory_scope_immutable`；`POST /api/conversations` 携带该字段同样被拒绝。
3. 相同 `requestId` 改变 `memoryProjectId` 返回 409 `request_conflict`；成功请求重放不重新处理记忆。
4. 接入真实 oMLX 后，在 A 项目问 A 的事实，证据为 `mem0-validated`。在有 A 历史的会话里问 B 的联系人，返回 409 `memory_scope_conflict`，不产生运行和消息，V6 刷新及重启后仍显示原因。
5. 停止 oMLX 后聊天仍完成，证据有 `fallbackReason`。
6. 项目任务运行中重启服务后重试 `context/retry`；项目已移除时任务变为 stale，且不产生记忆。
7. 签名包内 `scripts/mygo-package-runtime.mjs` 的 Mem0 与原生模块探针通过。

## 实现前失败清单

- 中文同义问法没有命中，或相近但无答案的问法注入错误事实。
- 新更正后召回旧状态。忘记、撤销、来源改动或删除期间，迟到的索引响应又带回旧内容。
- 多个工作区的记录混用。已有全局记忆不能被包装成已实现项目隔离。
- 框架把模型复述、外部来源或未核验的人事事实当作权威记忆，绕过原句证据和用户忘记入口。
- 索引失败、模型停机、维度不符、依赖缺失或冷启动阻塞普通聊天。重启后已有记忆仍可读。
- SDK 默认遥测、历史库和默认公网端点复制了资料或暴露了凭证。验收只用合成语料和本机模型。
- 框架 npm 包能在开发环境导入但不能随签名 macOS 包加载。源码、隔离环境和日常安装版分别验收。

## 对照口径

沿用现有隔离实验的冻结问题和匹配标签。比较关键词和 Mem0 的前三命中、无答案误返回，以及更正、忘记、来源失效与重启。先运行原始框架配置，再决定是否启用。星数用来筛选，记忆效果以实测为准。

试验比较 Mem0 的语义阈值 0.55，与同一候选池经本机 Qwen3 重排后分数至少 0.85 的路径。质量门槛为中文改写命中超过现有关键词，并将无答案误返回至少减半。权限门槛为工作区越界、已失效来源及忘记后的错误召回均为零。项目标签只在合成实验使用。

首轮重排仍会混淆相近的事项。第二轮用本机模型逐组判定事实是否直接回答问题。候选输出仍需核对原文，允许空结果。复用原有问题用于回归，并在实现判定器前登记另一组问法。启用门槛为原组至少命中 8/12 条中文改写，19 条无答案最多误返回 2 条，项目错配探针必须拒绝。新增组至少命中 4/6 条有答案，6 条无答案最多误返回 1 条。

源码试点仅允许在独立合成数据库开启。验证真实左侧聊天收到经核验的原始记忆、另一会话能召回、模型不可用时聊天仍能完成、后台记忆写入及忘记入口沿用既有流程。嵌入和核验期间，若原文变化，已批准的旧片段必须被丢弃。

范围过滤能剔除别的工作区及未授权项目的候选，原句更正、忘记、修改和重启检查通过。唯一剩余的无答案误召回是项目身份冲突：在海岬的范围里问晨舟的客户需求，候选仍被模型误判成可回答。合成实验有项目标签，日常版的全局槽位写入与忘记还没有项目作用域。项目错配门槛未过，日常版继续使用现有记忆路径。

真实 HTTP 的 5 项试点检查覆盖自动记住原句、跨会话语义召回、无答案拒绝、嵌入认证失败时继续聊天及忘记。真实浏览器在原界面换一种说法提问，核对最终回答和运行证据。浏览器截图的两条「记忆整理未完成」来自测试在两条后台作业结束前重启服务，后续复验脚本会等待后台作业结束再重启。原自动记忆扩展 HTTP 13 项回归通过。本轮没有迁移真实数据或替换日常安装包。签名包的原生依赖装载仍需独立验证。

## 复验

本机 oMLX 服务须可访问 `127.0.0.1:48000`，并已配置上述嵌入、核验及 Qwen3-Reranker-0.6B-mlx-8Bit。只使用合成数据。隔离 npm 依赖及向量数据库保存在 `.local/mem0-evaluation/`，测试报告和截图在 `output/mem0-memory-20261109/`。

```sh
npm install --prefix .local/mem0-evaluation/sdk --save-exact mem0ai@3.3.1 better-sqlite3@12.6.2
node --import tsx scripts/mem0-memory-e2e.mjs --judge
npx vite build --config web/mygo.vite.config.ts --outDir ../.local/mem0-pilot-web
node --import tsx scripts/mem0-chat-pilot-e2e.mjs --serve
ego-browser nodejs < scripts/mem0-chat-pilot-browser-e2e.mjs
```

浏览器地址 [http://127.0.0.1:46953/](http://127.0.0.1:46953/)。先启动 `--serve`，再在另一个终端运行浏览器检查。评估 API 端口为 46951，主聊天试点 API 为 46952，测试模型代理为 46954。
