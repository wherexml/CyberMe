# 窗口拖动与关闭

CyberMe 0.1.6 本机修复（2026-10-24）：

- 灵感、任务页标题及其上方留白支持移动原生窗口。
- 设置顶部38pt空白区支持移动所属原生窗口，标题栏中的关闭按钮仍正常工作。
- 「文件 → 关闭窗口」提供 Command+W：先关闭当前弹窗或设置，没有弹窗时走原生窗口关闭流程。
- 输入框、按钮、链接、可编辑内容和侧栏分隔条不触发窗口移动；释放指针后忽略迟到的定位结果。关闭弹窗遵守 cancel 事件。

窗口桥接仅作用于调用方。后台服务生命周期沿用既有行为，不因本次窗口修复改动业务执行或数据协议。

## 2026-11-06 内容入场动画与空白窗口

失败面：原生后台窗口曾出现 DOM 已更新而聊天/卡片不可见，重新置前后恢复。可重复暂停入场动画后，原 `cmIn/cmRise/cmSlide/cmPop` 的首帧 `opacity:0` 会让内容一直不可见。

修复：这些内容入场动画首帧保持 `opacity:1`，保留轻微位移动效；内容读取不再依赖 WebView 动画时间线推进。未增加轮询重绘或修改系统节能设置。暂停时间线是确定性回归条件，不据此宣称已经查明 WebKit 内部调度停止的原因。

本轮安装验收：build `1793935440757` 已替换本机应用。两次打开、简报/决策/灵感/任务切页及主动隐藏恢复，内容均可见。候选签名和安装哈希一致；这组实际窗口观察与首帧暂停回归分别保存，不以浏览器结果替代原生结果。

## 2026-11-07 V6 跨屏拖动

失败面：原 V6 使用 WebKit `screenX/screenY` 差值，经异步 `Position/Move` 桥接反复设置窗口位置。不同显示器原点、高度或缩放变化，以及迟到的移动请求，都可能导致跳变；原生拖动与网页移动不能同时运行。按钮内部图标、开关、分隔条和可编辑区域不能误触拖动；React 更新、松手与双击也须保留既有交互。

V6 两处标题空白改用 MyGO `--app-region: drag`，直接进入 AppKit `performWindowDragWithEvent:`，移除网页坐标运算、指针捕获及逐帧移动请求。交互元素及其后代显式标为 `no-drag`。双击由同一个原生桥接处理，遵循 macOS 标题栏双击设置，不再额外调用网页放大。Command+W 保持原有前景页面关闭规则。仅改变 V6 入口，历史经典 QA 页的旧桥接不属于本次修复。

复验：先运行 `npx vite build --config web/mygo.vite.config.ts --outDir ../.local/window-drag-web`，再运行 `node --import tsx scripts/window-drag-fixture.mjs` 和 `ego-browser nodejs < scripts/window-drag-browser-e2e.mjs`。隔离 URL 为 `http://127.0.0.1:46828/cyberme.html`，使用合成数据、真实页面与 MyGO JS bridge，原生消息仅记录。13 项页面检查通过，含双标题、单次双击、按钮后代排除、分隔条调宽、草稿保留、React 重装与刷新；类型检查及桌面构建通过。原生跨屏、安装与签名结果单独记录，浏览器消息记录不能证明屏幕无闪动。

本机 build `1794045588573` 已签名安装，6 项安装/进程/健康检查及数据保留检查通过，后端运行时复用安装前原字节。原生页面启动与放大还原已观察；自动跨屏尝试未取得窗口越过显示器边界的证据，因此真实跨屏无闪动仍为 **NOT_VERIFIED**，不同缩放屏幕未覆盖。未公开发布或重新公证。
