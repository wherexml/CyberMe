# 灵感主对话提醒

2026-11-10 起，自动洞察的单条提醒与摘要均须等当前图形通过独立复核。待图的摘要项继续等待且不占摘要名额。新投递绑定当时通过复核的图形版本，版本失效即撤回对应提醒或摘要行。同一证据重新出图不重复提醒。已有聊天历史遵循原有证据撤回规则，旧提醒不会补投到 macOS 通知。

> 2026-11-08：新洞察按现有设置投递：`every` 单条，`urgent_digest` / `digest` 进入摘要。`information` / `delegation` 可以作为只读更新投递，不创建本人待办；摘要追问沿精确洞察和来源复核加载最多6项。历史、去重、撤回和授权边界保持。本条替代下文“默认不进主对话”和“信息/委派不提醒”，见 [视觉与推送恢复](insight-delivery-recovery.md)。

2026-11-06：提醒的新鲜度改为具体触发证据的消息时间，历史消息不能借用同会话的新活动时间；本人身份和责任校验升级，旧聊天派生提醒须重新核对。见 [分析身份与时间](analysis-identity-and-time.md)。

> 2026-11-05 起，投递规则以[注意力投递](attention-delivery.md)为准：灵感默认不进主对话；下文“不设时间窗或条数上限”“页面不提供执行按钮”“不附链接”在此范围内被取代。去重、撤回与复核规则继续有效。

失败面先登记于本文末尾；验收边界见 [验收说明](validation.md)。

`server/src/ideas-chat.ts` 把仍然有效的自动灵感投影为主对话中的派生 assistant 消息（`ideaAnalysis.kind='idea-insight-v1'`）。灵感记录始终是唯一事实来源；投影不调用模型、不执行、不外发，也不修改灵感生成与证据校验（`ideas-background.ts` 仅导出 `sources()` 供复核）。

## 投影规则

- 只写入 `primaryConversationId` 指向的主对话；不存在、已归档或为侧边会话时不写入。侧边会话不读取、不出现提醒。
- 可提醒的灵感：未删除、`status='new'`、`autoGenerated` 且非 `userManaged`、14 天内刷新、有 evidence；全部 `sourceIds` 当前可读（连接已连接且有读取权限、未被来源规则排除），且当前来源指纹与灵感记录的 `sourceFingerprints` 完全一致。
- 首次启用记录 `ideas-chat-v1.enabledAt`。启用前已存在或刷新的灵感不提醒；启用后新生成、但证据来源最新事件时间不晚于启用时间（历史积压）的也不提醒。事件时间无法解析视为历史。
- 不设时间窗或条数上限；来源重叠本身不压制不同事项。

## 去重与有意义更新

- 全局去重键 `hash(topicKey, evidence[sourceId+quote])`，持久记录在 `ideas-chat-v1.alerts`，重启后仍有效，提醒过的键不再新提醒。
- 同一灵感再次提醒还需证据来源指纹（provenanceKey）发生变化：仅改标题/描述、仅换引用句或仅改 topicKey 都不新提醒，已有消息内容保持当时展示的版本。
- 新提醒以新消息追加（消息 ID 由灵感 ID 与去重键派生），旧消息以 `superseded` 撤回。

## 撤回与恢复

- 每次同步按当前灵感（沿 `mergedInto` 解析）与当前来源复核每条在线提醒；失败即软删除消息并记录原因：`idea_deleted`、`dismissed`、`executed`、`merged`、`archived`、`stale`、`user_managed`、`superseded`、`source_changed`、`source_inaccessible`。
- 在线提醒（含展示与对话衔接）的复核：解析后的灵感全部 `sourceIds` 当前可读，且当前来源指纹与灵感的 `sourceFingerprints` 完全一致；所展示引用的来源仍在灵感 `sourceIds` 中，且这些来源自展示后未变化，或后台已在新版本上重新校验出相同证据（去重键相同）。仅因旧引用仍出现在已变化来源中不算有效；来源变化后（例如之后的取消消息）提醒以 `source_changed` 撤回，不加载过期灵感内容。
- 仅 `source_changed`、`source_inaccessible` 可原位恢复（不算新提醒），且须在撤回之后后台生成已按当前来源刷新该灵感（`refreshedAt` 晚于撤回时间）、去重键相同并通过上述复核。其他原因不恢复。
- 合并：多条在线提醒解析到同一存活灵感时，确定性保留一条——优先存活灵感自身的提醒，否则最早创建者（同时间按 ID）；其余以 `merged` 撤回且不恢复。保留者更新 `currentIdeaId`，存活灵感的账本采用其当前去重键与 provenanceKey，合并本身不产生新提醒。
- 用户自行删除提醒消息视为 `user_removed`，永不恢复。
- `GET /api/conversations/:id/messages` 返回 `ideaAnalysisIds`（该会话全部在线提醒 ID）；客户端据此移除缓存中已撤回的提醒，不影响分页外的人类消息、草稿与阅读位置。

## 对话衔接

- 提醒消息不进入普通历史、会话摘要和自动记忆（`contextHistory` 排除 `ideaAnalysis`）；Inbox 投影原有行为不变。
- 主对话普通回复且本轮没有明确选定资料时，服务端复核当前在线提醒（最多 6 条），把“展示版本 + 当前灵感 + 当前来源摘录”作为不可信来源资料加入提示词，并记录 `load_idea_reminders` 证据（消息/灵感/来源 ID 与指纹）。它不进入工具授权判断，不构成执行授权，不得保存为记忆或偏好。
- 本轮 `contextIds` 精确加载的资料优先，已点选资料时不加载其他提醒；单选后说“这个 / 你怎么看”直接围绕该项作答。多选且确实无法消歧时只在所选资料内澄清。标题、正文引用与明确会话指向也可确定对象，不能仅凭“这个”触发确认。只有缺少明确指向且存在多个候选时才列候选标题；未进入最近六条提醒不等于已撤回或不存在。
- 提醒气泡附“打开灵感”，只对该消息记录的当前灵感 ID 打开灵感详情；页面不提供执行按钮，执行仍走灵感页面原有入口。

## 失败面（实现前登记）

1. 首次启用时已有大量灵感与来源：主对话不新增任何提醒；启用后由历史积压来源新生成的灵感也不提醒。
2. 启用后新来源产生的灵感：主对话恰好一条提醒，含标题、描述与逐字引用；不暴露原始 ID。
3. 后台仅改写措辞或换引用句：不新增、不改写提醒。
4. 同一事项出现新证据（来源变化且引用变化）：追加一条新提醒，旧提醒撤回；重启后不重复提醒。
5. 同一来源中的不同事项：分别提醒，不因来源重叠被压制。
6. 忽略、删除、执行、合并、归档或过期：提醒在下一次同步撤回，客户端下次加载后消失；同证据不复现。
7. 来源连接失去读取权限或来源删除：提醒撤回；权限恢复后须待后台刷新该灵感且证据不变才原位恢复，不算新提醒。
8. 来源出现新消息（指纹变化，含随后的取消/改期）：提醒立即撤回，追问不加载旧灵感内容；后台刷新后证据不变才原位恢复，证据变化则按第 4 条处理，灵感被退役则不恢复。
9. 用户删除提醒消息：不恢复、不重提。
10. 侧边会话、已归档主会话或无主会话：不写入提醒，侧边会话回复不加载提醒。
11. 用户追问“为什么/怎么做”：运行记录含 `load_idea_reminders`，回答基于复核后的当前来源；无用户明确请求不调用写工具；提醒内容不进入自动记忆或会话摘要。
12. 多条提醒时用户只说“这个”：模型先确认所指，不猜测。
13. 撤回发生在客户端当前页之外：缓存提醒被移除，不丢失草稿、不跳动阅读位置。
14. `invalid_evidence` 等灵感生成失败：不影响已有提醒；本模块不改变其行为。
15. 两条已提醒的灵感合并为同一存活灵感：只保留一条提醒（确定性选择），其余撤回；不新增提醒，重启后不复现重复。
