## 产品 Agent skill

原链路的提示词内联在 TypeScript 中，通用 Agent 的资源加载仍为 `noSkills:true`。现在由洞察服务显式加载固定产品技能 `server/agent/skills/insight-visuals/SKILL.md` 及同目录 `generate.md`、`review.md`，不扫描用户或开发工具的全局 skills，不开放工具。三个文件作为公开运行资源打进 App。

- `SKILL.md` 沉淀角色与证据抽取、关系选择、不确定性、对象与字段基数、事件身份/阶段、字段完整性、说话人归属，以及与真实渲染器一致的父子范围、条件归属和连线方向。生成与独立复核都读取同一技能规则。
- `generate.md` 定义有限视觉语法；`review.md` 定义六项复核和结构化结论协议。没有业务 ID、固定案例分支或逐条手写图形。
- 固定加载器检查文件大小、非空内容、前置元数据和协议占位符；文件缺失或非法时读取回退原文，显式生成报技能不可用，不回退旧提示词。
- 三个文件内容和加载器版本共同参与 skill hash；每次调用记录 skill ID/version/hash 与实际提示词摘要。技能、来源或模型变化均使旧缓存失效，读取不会因此触发新模型调用。
- 通用 Agent 仍关闭自动技能发现；这条能力通过显式注入产品技能运行。不要把全局 `noSkills:true` 误读成该技能没有执行。

## 链路

已保存的灵感标题与正文（I）和逐字证据（E0…），经过下列步骤：

1. 规范化输入：只取这条灵感自己的标题、正文和最多 6 条证据引用，不读其它业务数据。
2. 当前可读性与证据锚点：来源必须仍在当前连接与读权限之内（与灵感分析同一规则 `sources()`）。每条引用必须落在当前仍存在、未撤回的那条消息中：有 `messageId` 就精确绑定，没有就必须恰好只在一条有效消息里；有过消息的记录不再退回记录正文。
3. 模型：复用现有模型与账号，类型为 `insight_visual` 的无工具、只读运行。仅官方 DeepSeek HTTPS `/anthropic`、字面 DeepSeek 模型名的洞察请求，经 `server/src/model-transport.ts` 选择同源 Chat Completions 并开启 JSON mode；保存的配置、普通聊天、其它生成器和第三方网关不变。有效 API/路径参与缓存指纹。官方兼容接口仅支持 `output_config.effort`；JSON mode 需 `response_format.json_object`，仍须处理空输出或无效结果。[Anthropic 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)
4. 编译与校验：`shared/insight-visual-compiler.ts` 归一化有限语法并逐块校验，第一个主图必须有效；可选支持块可整体删除并标记 `reduced`，不能删掉关系内部的列、节点或轴来凑成功。结构有效的图必须再经过一个独立、无工具模型调用，检查标签、值、归属、时间、关系基数与跨字段语义。复核结论严格校验六项检查、问题路径、代码及逐字证据；只有 pass 且零问题可发布。一次尝试最多三次生成（首次、一次结构修复、一次语义修复）加两次复核，共五次模型调用。复核拒绝、畸形或服务不可用时，不发布未经通过的候选。
5. 原卡片始终保留已保存标题和摘要；模型只生成补充图形，不写新标题/摘要。图形有效时摘要视觉折叠到三行，点击打开原详情；原文数据不变。
6. 缓存：独立表 `insight_visuals`。只存派生结果，不改灵感记录、状态、时间或注意力状态。
7. 渲染：`web/src/v6/InsightVisual.tsx`，只按通用块类型渲染，不执行模型给出的任何标记或动作。

**缓存键**包含以下几项，任一变化都使旧视觉失效：

- 格式版本；
- 技能内容 hash、加载器和生成流水线版本；
- 提示词与校验规则版本 `INSIGHT_VISUAL_POLICY`（改任何校验规则都必须升这个版本）；
- 非敏感的模型渠道身份：协议、来源地址、规范化路径、模型名、部分模型参数及实际推理级别，不含密钥与查询串；
- 规范化输入；
- 每条证据所在消息的锚点：消息 ID、修订、正文、发送者和时间。

同一会话里无关的新消息不会使视觉失效；被引用消息被编辑、撤回、删除或改了署名，视觉就会失效。视觉只展示灵感自己保存的文字，不代表来源现在依然成立；灵感本身是否过时，仍由现有灵感流程处理。

## 生成与成本控制

- `GET /api/ideas/visuals` 与 bootstrap 只读，绝不触发模型。
- 显式生成每次请求最多 6 条，全局队列上限 12 条且原子判断：放不下就整体拒绝。队列单并发，在途 ID 去重。每次调用后立即持久化调用次数；每天调用上限默认 60 次（`CYBERME_INSIGHT_VISUALS_DAILY_CALLS`）。
- 同一输入的结果：
  - `ready`、`invalid` 或 `rejected` 为当前指纹的终态，不能通过反复请求绕过修复上限；
  - `failed`、`interrupted`、`discarded` 在尝试次数上限内可以再试。
- 遇到额度错误（429 等）：
  - 暂停 30 分钟；
  - 队列中剩余的项不再调用；
  - 期间显式请求返回 429。
- 重启时，在途项记为 `interrupted`，不会自动无限重放。
- 迟到结果：提交前重新计算来源、模型及技能指纹与可读性，不一致就丢弃。
- 复核通过记录绑定最终图、输入证据和技能 hash；读取投影重新核对这些绑定并执行结构校验，旧的仅结构通过缓存不能显示。
- 仅 `insight_visual` 且现有配置 `modelOptions.reasoning === true` 时使用 high 推理，单次供应商超时为 90 秒；其它运行仍沿用原设置，不更换模型或账号、不修改保存配置。记录实际请求的 thinking/effort 与 JSON 输出标志，不记录推理正文。

## 界面

简报页的“决策 / 灵感”分页合并成一个“洞察”流，去掉了主题筛选墙，卡片不再显示分类名。顺序：执行中事项 → 待决定请求 → 其它请求洞察 → 灵感卡片 → 已选择的请求。

## 校验边界（如实说明）

强制检查：

- 引用必须逐字存在；仅固定通用缺失词（未提供、来源未提供、未说明、待提供、未记录）的 `not-provided` 可用空依据，不得夹带数字、说话人、限定或事实断言；
- 装饰标签中的数字/日期须存在于输入，完整日期不能靠零散数字凑出；版式前后示意必须有版式内容依据，业务或数字变化不能画成假版式；中性对应用 `corresponds`，不伪装成不等或未知；
- 显示的数字和日期必须出现在自己的依据里，相邻的“约 / 一般 / 最高 / 或 / 工作日”等限定词必须保留；输入中任何一处带工作日限定的数字，显示时都不能丢掉该限定；
- 引述类文字本身必须逐字出现在依据中，且前面不能是否定词；
- “已完成 / 已确认”等完成断言必须在依据中原样出现，且没有被否定；
- “不存在 / 没有”等否定说法要有依据；依据只是“检索不到”时，文字必须保留检索或记录的限定；
- 建议段落的内容只能显示为“建议”；
- 矩阵格子要有写明同一状态的依据；
- 映射的 `same` 要求两侧都已知且文字相同；
- 比较表只有完整数据单元一致时才合并为“相同”；
- 来源列出的列或栏要么全部出现，要么列入“未展示”；
- 未知组件、标记或 URL、动作字段、畸形结构一律拒绝。

语义检查与边界：

- 独立复核覆盖批注、单位、立场、说话人、分组、维度、对应关系与阶段，不再仅依赖逐字引用存在。拒绝理由也必须绑定资料中的逐字证据。
- 复核仍由同一配置模型的独立调用完成，不是形式化语义证明，可能误判或漏判；固定真实样本与未见样本的人工作图核对仍必要。
- 显示的标题和摘要固定为原内容；灵感本身是已有 AI 解读，不是经外部核实的事实。

## 实现前失败面（2026-11-06，先于代码登记）

来源：独立视觉实验与协调方复核。下列示例都是合成描述，不是业务数据。

| 编号 | 场景 | 必须成立 |

| V4 | 模型标题或摘要写了新的数字或断言 | 产品完全不采用模型标题/摘要，始终保留原卡文字 |

### 实现中复核补充（2026-11-06，先于修补登记）

| 编号 | 场景 | 必须成立 |
|---|---|---|
| R1 | 原始来源消息被编辑或撤回，灵感记录本身没变 | 当前来源指纹与灵感保存时的指纹不一致，或证据已不在当前来源中，就不返回旧视觉、不生成；迟到结果同样丢弃 |
| R2 | 生成完成时没有新的工作区修订；新修订到达时还有旧 GET 在途 | 前端在有待生成项时有界轮询；修订变化时立即清空已缓存的视觉，丢弃旧响应并补发一次读取；撤权期间不闪出旧视觉 |
| R3 | 依据逐字存在，但显示文字改了意思（“尚未完成”显示成“已完成”）；格子标“已确认/未执行”而依据只是任意一句 | 引述类文字本身必须逐字出现在依据中且前面不能是否定词；“已完成/已确认”等完成断言必须在依据中原样出现且未被否定；格子状态需要与状态匹配的明确依据，否则拒绝。这是保守的词面检查，不是语义蕴含证明 |
| R4 | 并发的显式生成请求不断追加队列；在途失败的调用次数丢失；额度暂停时仍可显式重试 | 全局队列上限、在途去重；每次调用后立即持久化调用次数；额度暂停对显式请求同样生效 |
| R5 | 映射行标 `same`，但两侧文字不同或一侧未知 | 两侧都已知且文字相同才允许 `same`，否则拒绝 |
| R6 | 畸形结构（空边、null 行、深层嵌套 split）或缓存里的坏视觉 | 校验返回无效，不抛异常；前端渲染失败回到原文，不影响页面 |
| R7 | 真实冒烟：123 条当前灵感中 121 条因整段来源指纹变化（同一会话后续出现无关新消息）被判为过期，全部显示原文 | 失效粒度改为证据级：只看引用所在的那条消息是否仍存在、未撤回、内容仍包含引用；缓存键用这条消息的内容哈希。同一会话里的无关新消息不再使视觉失效；被引用消息编辑或撤回仍会失效。不读取有界摘录，而读取当前完整记录 |


### 语义与技能失败面（修补前登记，2026-11-06）

| 编号 | 场景 | 必须成立 |
|---|---|---|
| S1 | x/y 数字存在，但未说明是日期或比例 | 不擅自命名角色，保留中性原文记号或原话 |
| S2 | 类别可选值与每项必填字段同时出现 | 不按数量或顺序逐项配对；每个字段及“或”限定完整保留 |
| S3 | 再次/复测与第一次混淆，同一事件更新了安排 | 阶段不改；旧安排/新安排须可辨识，不增加日期精度或事件次数 |
| S4 | 框外执行等待批准，框内准备可先做 | condition 在框内渲染，只能约束框内；外部事项的前提留在该项里 |
| S5 | 单个引用正确，父组、表头、行维度或步骤条件改变了意义 | 生成与复核共用真实渲染语义，整组检查主体、时间、阶段与权限范围 |
| S6 | 生成器自我认证、复核缺项或伪造否决证据、审批对应别的图 | 只接受独立且完整复核，绑定图/输入/技能 hash；不合格回退原文 |
| S7 | 技能缺失、空文件、更新中、打包遗漏或旧缓存 | 不回退旧提示词；无工具只读检查，技能更新使旧图失效，迟到审批丢弃 |

语义 HTTP E2E 覆盖 S1–S7 的管线门禁、纠错、真实技能注入与缓存竞态；受控供应商并不证明真实模型能识别每一种语义错误。真实模型与人工复核单独记录。
