# 明确交办的通用执行

## 实现前失败面（2026-11-06）

1. 用户明确要求测试、查询、下载或修复，但主聊天只有业务工具；将工具缺失说成用户未授权。
2. 凭证使用和泄露混为一谈；密钥复制到模型工具参数、命令参数、日志、错误与验收文件。
3. 引用、来源、否定请求、自动摘要或只读会话获得执行能力。
4. 网络、命令或文件操作没有真实回执；非零退出码被当成功；认证与推理成功混淆。
5. 重复 operationId、Chat 重放或进程重启重复执行；中断后子进程继续写入。
6. 输出无界、命令永久挂起、目录不存在；原结果和未知状态不可回查。
7. 凭证来源不唯一、失效连接或错误目标；运行使用过期凭证绑定。
8. 工作区通过但安装版仍运行旧提示词和工具。

## 契约

普通主/侧聊天的直接操作请求可使用 `get_execution_context` 与 `run_command` 完成网络、命令、文件工作。执行器使用当前应用所属用户的本机权限，并非文件系统或网络沙箱；后台分析、起草和显式 readOnly 不提供该工具。用户明确禁止的操作仍禁止，已有业务动作优先使用，不能利用命令绕过发送、暂停或来源权限。

操作参数携带当前请求的逐字 evidence、稳定 operationId、command，以及可选 cwd/timeoutMs。默认目录为应用数据根；指定目录必须真实存在。每次最多 60 秒、输出最多 64 KiB，超限/超时/打断终止该命令进程组，结果保持未知或部分完成。不得以非零退出码或模型回复完成宣称任务完成。

已有模型凭证和本轮实际读取资料中的可识别密钥通过运行内引用注入子进程环境变量。引用不含密钥值，不持久化值；模型只看到引用和脱敏内容。已有 CLI 登录直接由 CLI 复用。不要扫描钥匙串、无关凭证文件或要求用户重复提供已有登录。凭证只能用于用户指定或已确认的服务，缺目标时先查资料，仍不明确才澄清。凭证探测先用最小请求，认证、模型可用性、额度、实际推理分别报告。

执行前持久化意图，审计保留操作 ID、命令摘要、退出码、耗时和输出大小，不保存命令正文或输出正文。相同 ID 回放已知结果，不同参数冲突；已启动但未确认的操作禁止自动重放。Chat 仍沿原 requestId 回查。

查看 GitHub PR 优先用 `read_github_pull_request`，仓库与编号必须从当前请求或已核实上下文确定。通过本机已有 GitHub CLI 登录并发读取概况和一页文件，每次最多 12 个文件，单个 diff 最多 1400 字符，明确返回分页与截断信息。固定 GitHub.com GET，不经 shell；记录读取结果与错误类别，不把读取计入写入回执。通用命令仍按可能写入保守处理。读取后模型超时可显式重试；存在真实或可能的写入则保持部分完成和防重放。
