## 关键约束

- 召回前核当前活动记录、内容摘要、来源有效性和模型标识；向量索引只是可重建的派生数据，不能把被替代、已忘记、来源改变的记录重新带回上下文。
- 试验显式提供 `global/cape/dawn` 项目范围，再做候选过滤。**生产当前尚无这一项目范围契约，向量相似度也不提供项目隔离**。指标分别列出现有无范围关键词、加范围关键词和加范围混合召回，不能把范围过滤收益全部归因于向量。
- 小语料试验对全部向量结果过滤后再取前三；规模化接入需要在索引查询前按权限/项目过滤，或足够 overfetch 后过滤，不能在截断候选后冒充完整召回。
- 固定阈值可能漏掉正确同义表达。不得根据此小样本调整后宣称泛化效果；至少需独立验证集、更多近似负例和拒答指标后决定是否生产接入。
- 种子写入走真实来源校验与记忆存储、纠正/忘记走真实模块 HTTP；本次不评估聊天模型的自动抽取质量，也不把受控种子当真实用户历史。

### 设计要点

- **关键词资格独立于向量索引。** 资格只来自权威活动来源和单独的 `experiment-scope.db`。向量缺失、`index_meta` 缺失、模型不符、内容摘要不符或嵌入失败，都只拒绝语义候选，不影响关键词候选。来源变化或手写记忆被移除才算真正失效，此时所有路径都必须排除。
- **范围必须显式。** 没有范围记录的条目不会被当作全局条目，而是被排除并计数。四路分别报告：现有关键词、带范围关键词、带范围纯语义、带范围混合。
- **覆盖缺向量与手写记忆。** 已知关键词条目和手写记忆不写入向量，带范围关键词和混合都必须返回；也要确认它们不会跨项目返回。
- **同槽碰撞探针。** 通过 HTTP 调用未修改的 `rememberFact` 和 `revokeMemory`，槽位不含项目名，记录每步前后的 ID 与状态，覆盖两个方向。
- **用例扩充。** 12 条中文同义、8 条词面对照、8 条同主题近似负例、6 条答案仅在其他项目的问题；两道首轮无关负例单独分组。
- **完整重启。** 工作进程关闭 HTTP 和全部数据库句柄并退出后，全新进程重新打开持久数据，用持久化的查询向量运行同一份检索实现，覆盖全部已登记问题，不重新生成向量。结果逐路比较，并证明已忘记、已替代、范围外的 ID 不出现。子进程失败、非零退出或输出无效都判定为验证失败。

### 首次运行后的融合修正（事后决定，新一轮结果待本地运行）

本地协调方首次端到端运行：实验执行、完整重启和安全门均通过；五项跨项目同槽探针在每种顺序下均为能力失败，与源码推导一致，这些失败不因本修正改变。

同时发现 `mv-04` 在两种写入顺序下混合路径都未返回正确答案：未建向量的 `cape-oncall` 在带范围关键词中排第一（分数 16），但 RRF 只看排名并奖励同时出现在两个列表的候选，`cape-release`、`cape-owner`、`cape-budget` 因此占满前三。

修正策略 `retain-scoped-lexical-rank-1-v1`：若带范围关键词的第一名不在 RRF 前 K 条内，就替换第 K 条，并保持在第 K 位。策略不使用用例 ID、标准答案或分数下限，没有调整阈值、topK 或 RRF k，也没有修改冻结用例及其摘要。候选已经过资格和范围过滤，所以保留不会放行已失效或范围外的条目。

这项修正不是事前登记的：它是在同一批冻结用例上看到失败后才确定的，修正后的结果不能算作对它的独立验证，需要未见过的用例集再验证。

可能的精确率代价：
- 只有一个二字词重合的弱关键词命中，也可能挤掉第 K 位更好的候选；这里有意不设分数下限，以免引入新的调参阈值。
- 负例问题可能换成另一条范围内的无关结果。保留只在结果已满时发生，不会单独把空结果变成误返回。
- 第 K 位原本正确的答案可能被挤出，使 Hit@3 或 precision@3 下降。
- 保留项停在第 K 位，因此无法提升 Hit@1。
- 关键词同分时按时间排序，第一名可能随写入顺序变化。

为便于核对，报告新增对照路径 `hybridRrfOnly`（修正前的纯 RRF），它同样接受安全检查；`lexicalRetention` 逐条记录被保留和被挤掉的条目。

### 如何读报告

- `harness.status` 只表示实验是否完整执行；PASS 不代表能力达标。
- `criteria` 分为 safety、capability、quality、evidence、gap。`decision` 取 `NO_GO`、`INCONCLUSIVE`、`NO_BLOCKER_OBSERVED_NOT_PRODUCTION_APPROVAL` 或 `NO_DECISION_HARNESS_FAILED`，没有笼统的 PASS。
- `metrics` 按顺序、路径、分组列出 Hit@1/3、相关与无关返回数、precision@3（分母固定为 3，短结果集不抬高精确率，并附单答案下的上限）、无答案误返回率。空返回、范围外泄漏、范围内无关匹配分开计数。这些指标只作描述，未预设数值目标。

两种顺序都只有 `mv-04` 触发关键词第一名保留，以值班表替换预算；其他正确答案未被挤出。此策略是看到首次失败后提出的回归修复，不能当作独立泛化验证。混合路径仍有 16/45 个前三列表随写入顺序变化，其中 4 个第一名变化。

完整重启：每种顺序新建进程重新打开来源、范围、向量数据库，对全部 68 个查询重跑五路召回（含原 RRF 对照），两次均零差异、失效记录返回为零。纠正后新记忆命中、旧向量排除，忘记后不复活；缺向量、嵌入不可用、缺索引表及向量元数据失效的关键词兜底均通过。

安全检查 26/26 通过；能力检查 18 通过、10 失败；纠正质量检查 4/4；证据检查 12/12。10 次能力失败都是 5 类跨项目同槽探针在两种顺序的重复结果：现有生产仍按全局槽位纠正与忘记，无法满足项目隔离。错槽纠正另记 2 项 GAP，未覆盖模型抽取质量。范围过滤后的召回泄漏为零不等于写入和忘记具有项目隔离。

当前结论为 **NO_GO**。混合路径近似负例误返回 8/8，全部无答案误返回 11/19；命中收益不足以支持生产启用。安装版未更改，仍使用现有关键词召回。完整逐查询及重启报告保存在本机私有验收产物中。

### 已知能力限制

- **生产尚无项目范围契约。** 范围只存在于实验自己的数据库。按源码，`rememberFact` 按全局槽位取代旧记录，`revokeMemory` 忘记整个槽位，本机实跑已确认同槽碰撞探针得到能力 FAIL 和 `decision: NO_GO`。这是对现有生产语义的如实报告，不是实验执行失败。
- **同槽无法并存。** 经 `rememberFact` 无法让两个项目的记录在同一槽位同时处于活动状态，所以忘记探针在碰撞发生之后才进入整槽分支。实验不直接写表伪造并存状态。
- **关键词截断先于范围过滤。** `recalledMemories` 先截断为 8 条再过滤范围，带范围关键词可能丢失范围内条目；每条结果记录 `lexicalTruncated`。
- **其余语料仍人为分槽。** `work:cape-db`、`work:dawn-db` 等沿用首轮的分槽方式，隔离证据只来自碰撞探针。
- **未覆盖。** 共享槽位的 undo、模型自动抽取质量、正式 macOS 分发包中的动态库装载与签名、规模化时的索引前过滤。嵌入失败探针传入空查询向量，没有让真实服务失败。

本实验不切换生产召回，也不改变生产结构、前端、依赖、安装版或模型设置。
