# V6 模型设置

## 实现前失败面

- 当前配置已保存在安装版的私有根。V6 只读取固定的 `custom` 条目作为表单值，其他供应商只有名称，无法打开和编辑。源码版和安装版的配置根独立。
- 普通与深度模型分别重复渲染目录，点击一套后可能只修改一个内部角色。合并界面时，进入页面、查看配置及测试不能改写旧角色或历史会话。
- 模型目录读取挂起、失败或返回无效数据时应有重试入口。全新安装应能添加第一个供应商，错误配置文件不能被当作空目录覆盖。
- 供应商应按精确 ID 区分。编辑、禁用和保存不得丢失凭据、模型参数或其他配置。更改地址、协议或兼容模式后不能复用旧地址的密钥。服务器拒绝后保留输入，版本变更须先重读。
- 测试必须等真实模型结果。响应丢失、切页、刷新、服务中断或上游拒绝时，按同一测试 ID 查回执，不能把测试登记当成功或默默再发一次。显示可操作的错误类型，不显示上游原文或密钥。
- 历史 `chat`、`deep` 和后续会话在同一列表中按时间打开，保留原会话 ID、消息及草稿。

## 页面与接口

「设置 → 模型」集中显示当前模型、测试连接及供应商列表。选择页按供应商列出各自的模型，选项身份为 `providerId + model`。显式保存才将两个内部角色设为同一个精确选项，现有 role API 和历史会话模式继续兼容。

- `GET /api/settings/models` 在首次配置前返回空目录、空角色及 `version: "unconfigured"`。错误的配置文件或显式角色绑定继续返回错误。V6 在打开模型页时读取，十秒未响应则显示重试。
- 供应商详情以 `PATCH /api/settings/models/providers` 显式保存。目录包括启用和停用的供应商，选择页只显示已启用、具备连接配置的模型。API 只返回密钥状态。协议、地址或兼容模式变化时，服务器要求填写该连接的凭据。旧目录模型参数与后台扩展字段随编辑保留。
- 保存使用服务端版本检查。冲突后可以读取新版本并核对保留的输入，再显式保存。当前角色使用的供应商不能被停用，使用中的模型须先切换后移除。
- V6 连接测试提交 `requestId`、版本、`role: "standard"` 及 `wait: false`。服务端先落真实回执，再运行无工具测试。V6 保存本机测试 ID 和版本，按原 ID 查询。明确未登记时可显式用同 ID 再提交，回查失败时提供查询入口。终态失败展示脱敏的类别。旧调用仍可等待运行结束。

## 获取模型与批量测试的实现前失败面

- 新供应商只有手填空白行。抓取失败、供应商没有目录、目录为空、分页中断、重复 ID 或只返回不支持的模型时，保留手填和已有条目，错误不能被当成连接测试通过。
- 读取目录后必须明确选中再加入。重复抓取不覆盖已有参数、不留下旧地址的结果，也不保存或切换当前模型。
- 编辑了地址、协议或密钥时，测试必须用当前输入。旧密钥只用于原连接，不能跟随重定向或发送到新地址。旧供应商在界面隐藏兼容方式后仍应维持原连接。
- 批量测试按各模型返回真实结果，区分测试中、失败、成功和结果未确认。一个失败不抹去其他结果。超时、响应丢失、返回页面或进程重启时不得把等待当成功或盲目重发。
- 批量测试只发送固定短文本，限制并发和输出。持久回执不包含密钥、上游正文或业务会话。目录不发模型推理。

## 供应商目录读取与批量探测

供应商详情提供「获取模型」「批量测试」和「手动添加」。目录可搜索和多选，已有模型按精确 ID 保留参数。模型行展开后可编辑或移除。「保存供应商」写入表单，「保存」当前模型才切换普通和深度角色。

- `POST /api/settings/models/providers/discover` 使用配置版本及表单端点、协议和凭据。已保存密钥仅供原供应商、端点与协议使用。兼容目录及 Anthropic 分页在同源读取，DeepSeek 的 Anthropic 端点使用同源目录。请求时间、页数与响应大小有上限，结果按 ID 去重并标明截断。无目录时可手填。
- `POST /api/settings/models/provider-tests` 以 `requestId` 登记表单模型 ID，使用该连接运行固定短文本。全局一次一批，单批最多四路并发。同 ID 同参数回读原结果，参数变化返回冲突。端点、协议或密钥变更会清除表单上的旧目录与探测反馈。
- `GET /api/settings/models/provider-tests/:id` 回读每个模型的排队、测试中、正常、失败或未确认状态。服务重启后，已完成行继续可查，未完成行显示未确认。
- 旧 Claude Code 兼容配置随原地址和协议保留，旧客户端可通过原字段显式更新。V6 编辑器使用现有协议选项。

复验时先运行 `npm exec -- vite build --config web/mygo.vite.config.ts --outDir ../.local/v6-model-discovery-web`，然后启动 `node --import tsx scripts/v6-provider-catalog-fixture.mjs`。另开终端顺序运行 `node scripts/v6-provider-catalog-http-e2e.mjs` 和 `ego-browser nodejs < scripts/v6-provider-catalog-browser-e2e.mjs`。重复浏览器验收前启动新夹具。默认预览为 `http://127.0.0.1:46991/cyberme.html`。
