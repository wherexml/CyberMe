# 洞察来源时间、观察与本人待办

## 2026-11-07 约定

本节替代分析身份与时间规范中“information/delegation 不生成洞察”的旧约定。责任判断继续有效，但洞察展示与本人行动资格分开。

- 飞书纪要按已解析的会议时间保存 `eventAt`，不使用采集/创建/更新时间冒充事件时间。启动时从精确 `sourceId` 对应的本地原始纪要补齐缺失时间；不覆盖已有时间、人工正文或未知时间。后续文档内容未变也可补时间，正文更新仍遵守人工编辑保护。
- 事件时间及洞察策略版本参与来源指纹，已分析的旧资料在修复后重新纳入增量分析。重复启动不重写已经补齐的记录。
- 有最近24小时准确证据且有价值的信息更新、趋势判断和本人交办进展，可以保存为 `information` / `delegation` 洞察；Inbox容器已处理不应隐藏此类独立观察。忽略、删除、合并及去重保护保持。
- 观察类不产生本人任务，不进入主聊天提醒与系统通知，不自动附着于本人决定。明确本人请求/承诺继续沿用逐条身份、时间、投递档位和来源复核规则。点击洞察仍只准备对话草稿，执行必须有用户请求。
- 聊天快照为每条消息提供 `evidenceRef` 短编号，绑定来源ID、精确消息ID及版本。模型返回原文与短编号；服务端精确绑定并逐字核对。重复原文没有精确绑定仍拒绝；跨来源、冲突ID、伪造引用或生成期间资料变化不能通过。
- 兼容旧的精确 `messageId`；未提供ID且原文唯一时仍可补绑定。一次验证汇总各条引用错误，在一次有界修正中提供具体错误路径、原因及去重且有总预算的受限原文；未知来源列出快照来源供纠正。运行事件只记录路径和原因，不记录原文。不通过则失败，不放宽证据标准。交办进展可以将他人的最新进展放在首条，但完整证据集合须包含本人的交办引用；本人请求/承诺仍由首条证据证明。
- 推荐文案在内部模型输出使用同级 `recommendationLabel` / `recommendationPrompt` 字符串，保存时转为既有 `recommendation` 展示契约；旧嵌套输出仍可读取。观察类推荐分析影响，不强行要求本人补文档或创建待办。
- 官方 DeepSeek Anthropic 兼容配置的 `ideas_refresh` 复用既有同源 OpenAI JSON 适配。保持原账户、模型和参数；首轮强制只读检索，后续 JSON 输出；普通聊天和其他供应商协议不变，不修改已保存的模型配置。
