# 对话宽度与主动判断

## 实现前失败面（2026-10-25）

1. 隐藏的消息操作常驻占据右侧宽度；长回复过早换行，短消息却拉成整行。
2. 段落、编号和消息间距叠加；收紧后操作按钮遮挡正文、无法键盘访问或窄窗口横向溢出。
3. 生成提示禁止列表，投影又删除列表标记，造成独立判断连成大段文字。
4. 模型只复述当前片段，没有查询相关资料；把联系人评价当产品事实、缺少后续当作未完成。
5. 检索越过断连、撤权、排除来源；检索结果没有进入逐字证据校验，或运行中资料变化仍采用旧判断。
6. 调查变成无限查询或业务写入；新工具误开放给摘要、记忆提取等内部任务。
7. 更新历史提醒产生重复消息、改变原时间，或改动普通用户消息。

2026-11-05：安装版 DeepSeek 使用 Anthropic 兼容协议，调查首轮必须以对应协议指定工具；JSON 输出与有界修正、安装验证边界见 [本机主动提醒](desktop-notifications.md)。

- 气泡正文使用完整内容区，左右内边距12px，短消息按内容收缩；阅读区和操作位置遵循原有约定（见下方用户澄清）。
- 先给有依据的判断；多个独立行动使用 1、2、3 编号，不强凑三条、不加空栏目。简短说明理由、推荐做法和必要的不确定性。
- 自动灵感可在已有授权的本地缓存中进行有界只读检索。工具结果必须进入同一来源快照和证据复核；不允许业务写入或外发。

## 2026-10-25 用户澄清：气泡内右侧空白

用户指的是文字到气泡右边缘的空白，不是气泡外的操作区域。上一轮放宽阅读区、移动操作按钮是误解，本轮撤回这些布局变动，保留编号与只读调查。

实现前失败面：模型单次换行被强制转为 `<br>`、正文提前断行；段落带固定宽度或额外右内边距；左右内边距不一致；短消息被撑满；合并换行误删真正段落、列表、代码或用户手动换行；历史/新回复样式不一致。

修正目标：正文使用气泡完整内容区，左右内边距均为12px；助手普通段落中的软换行由浏览器自然重排，空行分段、Markdown显式换行、列表、引用和代码保持；用户输入换行不变。阅读区和按钮位置恢复原约定。

本轮浏览器复验：桌面气泡584px、正文560px，左右均12px；390px窗口气泡166px、正文142px，左右均12px，无横向溢出。普通软换行不生成br；空行保持两段、两项编号、用户手动换行、Markdown显式换行和代码两行均保留。阅读区恢复680px、操作恢复原位。仅生产组件隔离验收，未更新安装版。复验入口：`node --import tsx scripts/chat-bubble-reflow-preview.mjs`，访问46746端口的首页及`/narrow.html`。
