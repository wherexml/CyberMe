# CyberMe V6 桌面界面

## 简报洞察流

简报合并决策与灵感，依次展示执行中事项、待决定请求、其他请求洞察、灵感和已选择的请求。灵感保留已保存的原文，可附加经过证据校验和语义复核的图形。自动生成图形默认关闭。后端仍按内容指纹保存 AI 主题，当前洞察流隐藏主题标签和筛选。见 [洞察视觉](insight-visuals.md) 和 [灵感内容分类](idea-content-categories.md)。

## 2026-11-06 记忆资料库

记忆页改为个人总览和资料夹。总览仅显示真实身份资料，主题分类按原文只读索引，原始笔记沿用 Markdown 原标题，人物档案与自动记忆单独进入。旧 SOUL 文档使用独立的「身份与 Agent 设定」入口，不自动拆写正文；行为规则不作为个人摘要。人物页读取配置目录的原始档案与既有跟踪记录，显示资料日期、事件时间和来源，不创建任务。详见 [记忆资料库](memory-library.md)。

版本保存、冲突保留、草稿恢复和忘记门禁继续有效。2026-11-06：类型检查与 V6 构建通过，隔离 Chromium 主流程 25 项、恢复补充 6 项通过；覆盖三主题、1000/1400px 窗口、中英文、人物读取失败与移除、409 后章节重新定位及忘记竞态。验收数据为合成输入，未替换本机安装包，不等于原生 WebKit 验收。

CyberMe 桌面窗口默认入口改为 `cyberme.html`（React/TypeScript，源码 `web/src/v6/`）。左侧为对话，右侧为可拖动宽度的面板，四个主标签固定为「简报 / 任务 / 记忆 / 设置」，仅保留浅色、深色两种主题与中英文。

## 2026-11-06 主题精简

移除纸张主题的设置入口、主题类型、配色、Broadsheet 专属变量和 Source Serif 4 字体资源。只支持 `quiet`（浅色）和 `night`（深色）；旧 `paper` 或无效主题偏好沿现有 `sanitize` 路径回到浅色，保留草稿、引用和其他界面状态，浏览器与原生 Bridge 读取共用此规则。此前三主题验收记录属于历史结果；后续浏览器矩阵仅覆盖浅色与深色。

验证：类型检查与 V6 构建通过；`scripts/theme-browser-e2e.mjs` 的 14 项隔离 Chromium 检查通过，覆盖旧偏好回退、草稿/引用保留、两种主题切换及刷新、800/1400px 布局和专属样式/字体移除。截图与结果保存在本机忽略目录 `output/remove-paper-theme-20261106/`。此次仅修改源码，未替换本机安装包。

## 对话顶部渐隐

消息滚动区顶部使用固定 32px 的透明度渐变，文字、气泡与边框一起淡出，取代生硬裁切。渐变只作用于消息滚动视口，不影响头像、状态胶囊、输入框或右侧面板；内容顶部保留渐变高度加原有 8px 留白，确保滚到最上方时首条消息和加载更多入口完整可见。标准与 WebKit mask 同时声明，浅色与深色共用透明度规则。

## 数据与状态

- 业务数据全部来自现有 HTTP 接口：`/api/bootstrap`、`/api/conversations/:id/messages`、`/api/chat`（requestId 回执、`/api/chat/requests/:id` 回查）、`/api/chat/work/*`、`/api/settings/documents/{soul,memory}`、`/api/memories/automatic`、`/api/settings`、`/api/settings/models`、`/api/workspace/search`、`/api/ideas-console/capabilities` 等；不新增服务端写接口。
- 本机仅保存界面偏好与未发送草稿（主题、面板宽度、头像、决策日志、对话草稿、请求回执），原生环境写入 MyGO Bridge 状态文件的 `html:cyberme-v6-ui`，读改写保留经典界面的草稿。
- 选择简报选项只是把文字放入输入框；发送后才以 `contextIds` 关联原记录交给 CyberMe，卡片显示“已交给 CyberMe”及真实请求状态，绝不显示为已完成。失败、结果未确认、部分完成、已停止均原样展示；只有确认失败或服务端未登记的请求可以显式重试，不会自动重发。
- 选择对话工作方向调用 `/api/chat/choices/:panelId/select`（含 revision 与 operationId），资料变化、选项过期由服务端拒绝并如实显示。
- 记忆卡片按 Markdown `##` 分节，逐节编辑后带 `version` 保存；版本冲突时保留输入并提示重新载入。「新建记忆」追加的默认标题为“新记忆”（英文 New memory），已有标题不变。
- 设置各子页保留 V6 的全部行与子页（模型、隐私与数据、账户、技能列表/详情/新建、连接详情）。有现成接口的行直接生效：自定义服务地址与密钥走 `PATCH /api/settings/models/providers`（密钥不回显）；“删除全部记忆”二次确认后以版本号保存空的记忆文档（服务端先快照，可在历史中恢复）；连接“立即同步”只启动飞书/微信的真实同步任务并显示其返回状态。没有接口的行保持原样、变暗并以悬停提示“当前版本暂不支持”，不加说明段落；套餐、用量、续费显示“—”。
- 技能页的行来自只读能力登记，开关只显示登记状态、不可切换；新建、移除、运行方式等没有接口，保持不可用。能力登记明细另有只读子页。模型角色选择与连接测试、权限与发送策略分别作为「模型」「隐私与数据」中的次级入口保留。
- 发送前请求回执必须已写入本机（原生 SaveState 或浏览器存储）；写入失败时不发送，消息保留并显示“未发送”与重试。
- 对话工作状态逐一保留：部分完成、已中断（可继续）、文件校验失败、已停止、结果未确认各自显示；非 `ready` 的方向面板也保留为“已选择 / 来源已变化 / 已关闭”，不能再选择。
- 助手消息使用与现有聊天相同的 GFM 解析（表格、引用、嵌套列表、代码），关闭软换行转 `<br>`，再经白名单清理；用户消息原样保留手动换行。
- 可视化（时间线、日历、对比、统计等）只在记录自身带有 `v6.visual` 时渲染，结构见 `shared/v6-visuals.ts`；生产环境不会生成示例数据。校验会拒绝未知类型、缺失或形状错误的数组、非有限数值；单个图表渲染出错只隐藏该图表。对话工作接口的公开投影保留可选 `v6` 字段。
- 邮件提案沿用 V6 模板（收件人、语气、创建任务、草稿审阅、结果卡、跟进）：起草走 `POST /api/inbox/:id/draft`；“发送 N 封邮件”先显式批准（`PATCH approved:true`），再以先落盘的幂等键调用 `/api/inbox/:id/send`，由服务端策略决定；结果卡只统计接口确认 `sent` 的项，其余如实显示原因；“未回复提醒”创建固定 ID 的任务。敏感事项尚未迁入 V6 审批，保持阻止发送；语气“简洁 / 温和”在创建任务前可选，随起草请求以可选字段 `tone`（`brief`|`warm`）传给只读起草提示；不传时与旧版行为完全相同。语气属于请求指纹：同一请求 ID 换语气会被拒绝（`request_conflict`），恢复或重试沿用登记时的语气；回执 `GET /draft-requests/:id` 返回登记的语气。旧版（无语气）请求记录只接受不带语气的重放，带语气时按冲突拒绝；采用已审阅的候选草稿时保留候选的语气。已有草稿只有语气一致时才复用（旧草稿视为简洁），语气不同且用户改过的草稿不会被覆盖，转为在 V6 详情中核对（不覆盖用户草稿）。
- 记录没有 `v6.visual` 时，仅用记录自身证据生成图表：决定卡取原线程中各发件人最近消息（日期列标为“最近消息”）；灵感卡仅在其关联来源全部属于同一发件人 ID 时，按这些来源显示近 12 个月频率；工作卡不生成统计（没有 `v6.visual` 时只显示步骤时间线）。证据不足时不显示图表。
- 记忆编辑在保存失败或版本冲突时保留在本机界面状态中，切换卡片、标签或重启后仍在；“重新载入”保留输入，只有确认“放弃修改”才丢弃。
- 第三方字体与图标许可证随构建输出到 `licenses/`。
- 品牌标识全部本地打包（`web/public/brands/`，来源见其中 README），按品牌键、产品名或参考域名匹配；匹配不到时才用通用图标。技能“使用的连接”绑定到真实连接，显示本地化名称与状态。
- 提案的起草请求 ID、发送幂等键和跟进任务都在请求前落盘；结果不明确时只读回查 `/draft-requests`、`/send-requests` 或任务本身，不会盲目重发；“已创建任务”只在服务端接受起草请求后显示。
- 视觉验收的设置示例通过 `PATCH /api/settings` 写入 `v6.fixture`（必须带 `synthetic:true` 才会生效），只用于隔离数据目录；界面经正式接口读取并用同一组件渲染。

- 悬停与按下反馈按参考稿机制生成真正的 `:hover` / `:active` 规则（带 `!important`），不再用脚本模拟；选中态、单选圈、飞入输入框与闪烁、标签滑块、拖动范围与窗口尺寸与参考稿一致。选择简报选项只在输入框显示引用，原记录在发送时内部关联，不显示额外上下文标签；改选另一项会替换自动填入的文字，用户手动输入的内容保留。全部决定完成时：未手动选过子标签则立即显示「灵感」（撤销任一决定即回到「决定」）；手动选了「决定」则 1400ms 后切到「灵感」，期间撤销会取消切换；之后均记为已选「灵感」。打开时已完成的简报：未选过子标签直接显示「灵感」，已手动选「决定」则保持「决定」，不自动切换。已决定卡片的「撤销」只移除该决定自身（按 `itemId` 精确匹配）的本机决策日志，其他决定、无 `itemId` 的旧记录、请求回执与工作记录保留，也不会撤回已发送的请求。选项的内部关联与自动填入片段随该对话的草稿一起保存，重启或切换对话后仍在；改选只替换未经修改的自动片段。右侧面板按应用窗口实际宽度保存比例（浏览器为受限窗口框，原生为窗口本身），范围为三分之一至三分之二，默认与双击复位均为 40%；拖动、键盘与辅助功能使用同一范围，不再使用固定像素下限。缩小、放大、隐藏后显示及重开均保持比例。旧版 panelW 像素偏好在首次测得窗口宽度后换算为 panelRatio 并清空旧值，仅迁移界面宽度，不改草稿等其他状态。面板内容（四个标签与详情）最宽 720，居中，多出的宽度成为两侧等宽留白；滚动条仍在面板边缘，顶部标签居中、隐藏按钮靠边。原生 WebKit 中 `all:unset` 控件显式清除系统按钮外观。任务页首次打开时展开第一张待确认卡片，用户收起后保持。详情与提案中的操作按钮与参考稿一致不带额外过渡（按下缩放平滑过渡）；例外：任务详情失败区的「重试」与参考稿 `retryStyle` 一致使用 `btn('primary')`，自带 `opacity 250ms` 过渡（覆盖全局缩放过渡，按下缩放即时生效）且没有悬停变色，参考稿中带悬停的是另一个「修复」按钮（当前未提供）；重试的显示条件与调用不变；发送按钮在没有内容时不禁用，按下仍有缩放反馈但不会发送。本对话中 CyberMe 正在回复（请求已准备或进行中）时，发送按钮与参考稿一样置灰（`--hover` 底、`--text3` 图标、默认光标），点击与 Enter 都不发送，也不执行已填入的方向或灵感选项；输入框仍可编辑，回复结束后恢复。未归属对话的请求按服务端规则归入主对话，只阻止主对话；其他对话不受影响。洞察详情的标题、描述、状态与颜色与灵感列表使用同一投影（含记录的 `v6.title`/`v6.summary`）。洞察详情恢复 V6 的「继续观察」按钮，仅在判断成功但明确缺少上下文（缺失上下文 ≥ 0.5 或结论/动作未知）时显示，敏感、判断失败或未完成、时间或来源不可用、发送失败等待核实情况不显示；按钮只填写输入框，不保存“观察中”状态，点击只把参考文字填入输入框并附上该记录，不直接执行；不再提供「在完整收件箱中打开」旧界面入口。任务详情在待确认时恢复「在对话中修改」（把来源记录附到当前对话输入框），仅在存在真实审批时显示「允许本次」。已选择的工作方向不提供“撤销”：选择已由服务端执行，本地撤销会误导状态。界面在 V6 根节点内统一使用 `border-box` 盒模型（与参考稿设计系统的全局规则一致；使用 `all:unset` 的控件仍按参考稿保持各自声明），因此输入框菜单宽 420、对话头部高 100、对话列外宽 720 与参考稿相同。

- 邮件提案的「查看任务」、任务创建事件的标题与「审阅」、结果卡的「任务详情」都在右侧面板打开该提案的原始任务（`p.task.taskId`，不是跟进任务）。详情按 V6 版式显示状态、标题、步骤、草稿区（仅在提案状态为“等你确认”时显示，含草稿预览、发送、逐行重试、再次核对、查看详情、继续起草、在对话中修改）、失败说明与发送结果，全部来自已记录的接口结果；打开详情只做只读核对，不会起草或发送。工作区尚未返回该任务时先按 ID 只读确认：确认不存在或已删除才显示“这项任务已不存在”，读取失败时显示可重试的“暂时无法确认”。「在对话中查看」滚动到该提案在对话中的位置并短暂高亮，必要时先切换对话。跨对话时等目标对话的历史返回后再平滑滚到提案顶部上方 100 并高亮 1400ms，期间初次滚到底与新消息滚到底不会覆盖该位置；再次跳转、切换对话、在对话区滚动或点击「回到最新」会取消尚未完成的定位。切换对话后旧对话的消息立即不再显示，也不会在后台刷新时并入新对话；只有本次进入后返回的目标历史才允许定位，历史返回即使消息数不变也会重新对齐；同一次进入中后发起的刷新尚未返回时，较早发起的慢响应仍会被接受，只丢弃比已接受响应更早发起的结果。连续跳转时每次高亮都完整保持 1400ms，较早跳转的计时不会提前清除新的高亮；取消定位不影响当前高亮按时消失。初次滚到底的计时只属于发起它的那次进入，切换、跳转或用户滚动后不再生效。所有执行按钮共用每个提案的忙碌锁，异常时也会释放。同一提案在对话与面板中同时显示时共用一个忙碌锁，不会重复执行。任务列表中该原始任务的状态、四步进度与排序，与对话事件和详情使用同一只读计算（按提案记录的每位收件人计算，任何收件人缺少“已发送”回执都不会显示为完成）；跟进任务和同名任务仍按各自的任务状态显示，服务端任务状态不被修改。
- 邮件提案与结果卡与普通助手消息一样，悬停时在行末显示引用按钮：提案引用其说明句，结果引用显示的结果标题（任务创建事件行没有）。点击只把文字（最多 800 字）放入输入框引用区并保存到当前对话草稿，不改动已输入内容、附件或关联，不发送。
- 已选择方向的工作卡（面板状态为 consumed）在展开后显示参考稿的绿色选择摘要：标题取自面板 `selectedOptionId` 在其自身选项中精确匹配到的选项名称，第二行仅在该选项有文字说明时显示；找不到对应选项时不显示摘要。状态标签仍为“已选择”（不是“已完成”），不提供撤销，也不触发任何执行。
- 已完成的工作卡可显示记录自带的后续选项（可选字段 `v6.followups`：`label` 为文本或中英对，`recommended` 可选；最多 4 个，无效项忽略），样式与方向选项相同；选择只把文字放入输入框并在发送时关联对应任务，不会执行或撤销任何工作。完成状态不再额外显示重复标题的绿色完成框。
