# 本地回复分析与静默冷却

2026-10-25。实施前契约，验证结果另记。

飞书本人私聊与明确 @ 本人的群消息沿用已有用户身份采集。来源已确认回复的请求先按消息关系过滤，不调用模型；新请求开启新一轮。群内无关发言不视为已答复。新消息后静默 180 秒再分析，重复同步不延长时间或重复分析，运行期间消息变化使旧结果失效。历史人工稿保留，旧审批失效。

本功能判断与草稿直接使用本机 oMLX，不回退 Jev 或其他云模型。模型输出是处理建议，不是经过校准的概率。回复仍需用户明确确认，不增加自动发送。

修改前失败场景：本人已回复仍调用模型；群无关回复错误清空请求；回复后新请求被旧状态抑制；冷却被默认草稿或来源 worker 绕过；重复同步/重启重复分析；运行中回复后迟到结果覆盖人工稿；模型断连/401/坏输出被当成功；旧审批发送过时草稿；模型输出被标成 Jev 概率；现有并行修改被覆盖。

验收：隔离 HTTP/SQLite/假上游端到端验证上述场景并保存逐项结果及调用次数，单独验证真实 oMLX 调用。生产同步保留原频率，不把同步拉取描述为官方个人消息推送。来源覆盖不足保留未知。

实施与验证完成：本机 20 项 HTTP/SQLite 验收、真实 oMLX 合成消息分析和起草、类型检查、独立应用构建签名、安装后的模块一致性和原生设置页面回读均已通过。可重复执行入口为 `scripts/inbox-omlx-cooldown-http-e2e.mjs` 和 `scripts/inbox-omlx-real-smoke.mjs`。本机详细证据见 `output/omlx-installed-20261025/ACCEPTANCE.md`（私有输出，不随公开文档发布）。既有采集的部分覆盖、未知旧记录与 self-test 发送限制仍存在，未宣称真实收件人发送验收完成。


## 2026-11-05 增量

普通请求继续复用同版本判断；用户明确“重新分析”会重新请求模型，仍受冷却与来源版本保护。过期自动草稿可重新准备，旧稿入历史，人工稿/手动稿/候选及未知请求不自动覆盖。见 [连接新鲜度](connection-freshness.md)。

## 2026-11-06 确认与致谢的无动作一致性

历史判断存在“确认/致谢、无动作、无未决请求、低优先级”与高回复分并存的问题，路由仍可能成为 `quick_reply`；若还有高缺上下文分，可形成不必要的核对提示。另有长历史、责任方向混淆造成的语义误判，不能只靠正文关键词解决。

- 生成结果与旧缓存读取统一经 `shared/inbox-judgment.ts`。仅成功判断同时具备 `actionType:none`、`resolution:none`、`priority:low`、`reason:acknowledgement/fyi/other_recipient`，且 owner/risk 都是有效低分（0–0.25），才规范为 `route:no_reply`，回复、深思、缺上下文分为0。原始 `answers` 保留；不伪造模型置信度，读取不改库、不调用模型。
- 不按“好的/收到/谢谢”匹配正文过滤。真实请求、决策、高 owner/risk、失败/未知/缺字段不适用；人工草稿、敏感、发送或生成结果未知沿用保护入口。
- 提示词改为一致的处理判断：可选礼貌回复不等于必须回复；连续来信中的未答问题不因最后一句谢谢消失。本人尚未履行的明确承诺可选其原消息作为决定的来源，不能作为向本人索要回复的来信；本人交办对方执行不属于本人承诺。绑定承诺的轮次由模型核对是否解决，普通本人后续发言不作为完成证据。
- 已确认的承诺轮次若被模型仅以 `acknowledgement` 改判为无动作，拒绝采用该矛盾结果，保留原始 `lastOpenRequest`；这记为判断失败后的保护，不伪造完成或模型成功。有精确后续完成证据时仍可退出。
- 不全量清空缓存或批量删除消息。已有完整无动作语义的缓存立即使用一致投射，其他来源沿正常版本变更或显式重新判断处理。
- 复验：`scripts/acknowledgement-http-e2e.mjs`（隔离 HTTP 46897、受控矛盾结果）、`scripts/acknowledgement-real-http-e2e.mjs`（HTTP 46896、实际本地 oMLX、公开合成消息）。产物保存在本机忽略目录 `output/acknowledgement-filter-20261106/`。
